# 文案规范

所有用户可见的中文都在 `iosApp/iosApp/Copy.swift`。视图里不写句子，不写标题，不写按钮的字。
这份文件写的是**怎么判一句文案算不算过**，评审照着它查；每条后面是它要拦下的那种错。

## 声音

第二人称「你」。短句，一句只说一件事。不用感叹号，不卖萌，不哄人。
术语优先用用户自己的说法；技术词能换成动作就换（「读列表」不是「拉取模型清单」）。

## 失败：说三拍，按顺序

1. **哪件事没成**——用「没 + 动词」这一家：没记上 / 没保存上 / 没拆开 / 没通过校验。新出的状态也照这个家起名。
2. **现在是什么状态**——尤其是账本：`账本没有任何变化` / `账本还是原来的样子`。第二拍必须让用户知道坏到哪为止。
3. **能不能再试、怎么试**——第三拍是一个动作，不是叮嘱。写「换一个模型再试」，不写「请重试」。

按钮承担第三拍时，文案里就不再重复一遍。

## 一次失败只说一次

同一时刻最多一条红的。按了哪个按钮，就在那个按钮底下说；别处的旧结论要清掉。
两条一模一样的红，用户会以为出了两个问题。

## 不写猜的原因

**没有证据的原因，一个字都不许写成句子。**

不知道就说不知道，说清楚什么是真的、下一步做什么。「可能已经下线了」「可能网络不好」比不说更坏——
用户记不住「可能」，只记住后半句，然后当成结论去行动。

判断标准：这句话里的因，我手上有没有一条能拿给用户看的证据？没有，就删。

## 不写没有先行词的「它」

前一句刚出现过两样东西的时候，代词会指错。管用户自己填的那个服务器叫**「服务」**，直接说出来：
「你填的服务说这个模型用不了」，不写「它说这个模型用不了」。

「它」只在上一句刚点过名、且全程只有一个候选时才能用。

## 数字

数字只在**大于零**时出现在句子里。「跳过 3 笔」要说；「跳过 0 笔」不说，整句删掉。
例外：**零就是答案的时候要说**——「账单 0 笔」是账本的真实状态，不能省。

## 不把版式写进字串

- 不写硬换行 `\n`。
- 不写靠空格凑出来的栏位。
- 不写字数固定、为了对齐而生的句子。

要分块，就分成两个键交给版式；要断开，就是两句，各自有句号。

## 短的只做退路

字号调大或宽度不够时，用短形式顶上；**短形式不是新名字**，不许顺手替掉代码里的原句，
也不许为了塞进去把意思削掉。不许缩字号，不许加省略号——那等于把最该核对的那几个字切掉。

## 术语表（一个概念只有一个词）

| 概念 | 用 | 不用 |
| --- | --- | --- |
| 用户填的那台服务器 | 服务 | 接口、端点、它 |
| 那家公司（DeepSeek、OpenAI） | 服务商 | — |
| 地址本身 | 接口地址 | URL、接口 |
| 凭据 | Key（后面不再跟「键」） | 密钥、token |
| 列表里挑的 | 模型 | — |
| 手打的那一串 | 模型名 | — |
| 数据本体 | 账本 | 数据、记录库 |
| 一条记录 | 笔（量词）/ 账单（列表里的那一行） | 条目、record |
| 未保存的解析结果 | 草稿 | 结果、预览 |
| 输入方式 | 一句话 / 手动 | 智能、AI 记账、手动模式 |
| 钱要记住的分类 | 分类 / 预算 / 规则 | 标签、限额 |

同一个动作不许有三个名字。今天改一处，明天另一处又冒一个，就是这一栏没人查。

## 红只给真失败

红色留给失败。**讲代价的不是失败**：明文地址那条讲的是代价，用正文色，配一个形状（三角）就够，
不红、不缩、不加图标以外的东西。

## 评审清单（每句过五遍）

1. 三拍齐吗？第三拍是动作吗？
2. 有没有一句话是我们没有证据的原因？
3. 「它」「这」「那」都有先行词吗？
4. 术语在表里吗，和同一屏其他句子用的是同一个词吗？
5. 数字该不该出现？版式有没有被写进字串？
