# 一句话记账成为主路径 — 交互规格

对象：`task.796a4ed1`。范围只有一件事——把「记一笔」从四次点击降到两次，让开了 AI 的人第一步就打一句话。
本次不动账本、不动统计、不动手动表单的结构（只在输入页留一个口子）。

---

## 1. 现在的路 vs 改完的路

| | 现在 | 改完 |
| --- | --- | --- |
| 1 | 点右下角「记一笔」 | 点右下角主按钮（AI 开着时就是一句话入口） |
| 2 | 在表单里点顶部的「一句话记账」胶囊 | 打字，按键盘上的「发送」 |
| 3 | 点「整理成草稿」 | 点「记上」 |
| 4 | 进确认页，点「保存 N 笔」 | — |
| **合计** | **4 次点击 + 1 个中转页** | **2 次点击（打开、确认）** |

键盘上的「发送」严格说也要按一下，但它属于打字这一动作的收尾，不是界面上的按钮——**屏幕里能点的按钮只剩「确认」一个**。这就是 Ato 说的「打字一次、点头一次」。

想再省掉「发送」只有一条路：停手 N 毫秒后自动解析。不做——每次自动解析都是一次真实的模型调用（花钱），而且写到一半就会被拆走，误发比多点一下难受。

---

## 2. 主按钮：外观不动，只分叉去向

判断只看 `ai.usesRemoteModel`（AI 设置里那个开关 + 有没有 Key），不新增开关。

| | AI 开着 | AI 关着 |
| --- | --- | --- |
| 文案 | 「记一笔」 | 「记一笔」 |
| 图标 | `plus` 15 semibold | `plus` 15 semibold |
| 底色 | `accent` + `onAccent` | 同左 |
| 尺寸 / 位置 | 高 44，胶囊，右边距 20，底边距 99 | 同左 |
| 点下去 | 打开一句话输入页，键盘直接起 | 打开「记一笔」表单（现状不动） |

我之前提过「AI 开着就把按钮改成『说一句』加 sparkles、换成紫色」，Camo 反对，Ato 也认了他的理由，我撤回这个建议：**按钮说的是要干的事（记一笔），不是怎么干（打一句话 / 填表单）**。用户一次只见到一种情况，不需要两个名字；而且跟着设置变形的按钮会让人以为它换了功能。紫色也一并撤回——如果外观完全一样，颜色就不该成为唯一区别（只靠颜色区分状态本身就是错的）。

所以按钮只有一个版本，`FloatingAddButton` 里只分叉 `state.showAdd` 之后去哪儿，外观代码一行不动。

首页空状态那句（`Copy.Home.emptySubtitleNoKey` / `emptySubtitleWithKey`）跟着 AI 状态分开写，AI 开着那份要说的是「说一句话就行」，不是「点下面的记一笔」——这是 Camo 的活，见 §10。

## 3. 输入页

沿用现有 `QuickAddView`，只改三处：进来就起键盘、输入框改单行、结果就地展开。

- 导航标题「一句话记账」，`inline`，左上角只有一个 `xmark`（现状的取消）。
- 整页背景 `canvas`，标题行 44。
- 输入卡：`card` 底，圆角 20，内距 18，卡内从上到下：
  - 标签行：`sparkles` 12 semibold + 「说一句话，出几笔草稿」12 semibold，`ai` 色（现状）。
  - 输入框：**单行** `TextField`，17 `ink`，行高 44，`.submitLabel(.send)`，`.onSubmit { parse() }`。进入即聚焦（`.task` 里 `focused = true`，等 0.25s 让 sheet 动画走完，否则键盘和 sheet 抢动画）。
  - 单行不是退步：一句话记账本来就是一句话；单行也保证下面的草稿卡不会被输入框顶出屏幕。粘贴长句时横向滚动，完整内容仍可编辑。
- 例句胶囊：保留，位置不变（输入卡下面，横向滚动，点一下填进去）。空输入时它们是「怎么打」的示范，第一次用的人最需要。
- 说明行 12 `ink2`：沿用现有三种说法（没 Key / 开着 / 关着）。
- 「改成手动记账」：13 medium `ink2`，44 高，放在输入卡正下方、例句胶囊之上（和现在一样的位置），把已经打的字带进表单备注——这条现状已有，别动。

## 4. 解析中

从按下「发送」到结果出来，**不跳页、不换屏、不清空输入**。

- 输入框变只读（`.disabled`），字不变，颜色掉到 `ink2`。
- 输入卡下面原地出现一行 44 高的状态条：小 `ProgressView` 16 + 13 `ink2`「正在拆这一句…」。
- 不做骨架屏：等的是 1–3 秒，骨架屏会让人先看见一堆方块再看见内容，反而更慢。
- 不做全屏遮罩：用户要看得见自己打的那句还在。

---

## 5. 就地确认（单个草稿、字段齐全）

结果是**一张草稿卡**，在输入卡下面展开，位置就是原来放例句胶囊的地方（例句胶囊收起，等确认完再回来）。**不 push 页面。**

草稿卡：`card` 底，圆角 18，内距 16，整卡可点（= 「改一下」）。

```
┌────────────────────────────────┐
│ ¥28                    [支出]  │   ← 金额 34 heavy rounded；类型小胶囊 11
│ ──────────────────────────────  │   ← 0.5pt line
│ 分类   餐饮                     │   ← 标签 11 ink2 / 值 15 ink
│ 日期   今天                     │
│ 账户   现金                     │
└────────────────────────────────┘
  [        记上        ]              ← 主按钮，高 52，整行
            改一下                    ← 13 medium ink2，居中，44 点击区
```

- 金额：34 heavy rounded，`monospacedDigit`；负数（退款）前面带 `-`，用 `income` 色。右端类型胶囊：`card2` 底、11 medium、`ink2`（支出/收入/退款）。
- 三行字段：标签 11 `ink2` 固定宽 40 左对齐，值 15 `ink` 左对齐；行高 32，行间 0。
- 只展示解析出来的这三项（分类、日期、账户）。备注不进这块——它经常是空的，空一行会让人以为漏了什么；要改备注就点「改一下」。
- 「记上」：`.pacePrimary`，高 52，整行，字 17 semibold。按下去 = 写账本（仍要用户按，见 §7）。
- 「改一下」：13 medium `ink2`，居中，上下各留 6，点击区 44；点了 push 现有 `DraftReviewView` 并直接把这张卡展开成编辑态。点草稿卡本身效果一样。
- 金额或值太长：金额用 `minimumScaleFactor(0.6)` 压一行；分类超过 6 个字截断成「餐饮聚会…」。

为什么不是三个都可直接改：就地三个字段各开一个 popover，等于把确认页搬进输入页，误触概率比多点一次高。这里只负责「看对了就点」，改是第二条路。

## 6. 什么情况仍然进确认页

解析回来之后按这两条判：

| 条件 | 去哪 |
| --- | --- |
| 只有 1 笔，且 `missingFields` 为空 | 就地展开（§5） |
| 1 笔但缺金额 / 缺分类 / 缺日期 | push `DraftReviewView`（现状），因为必须补齐 |
| 2 笔及以上 | push `DraftReviewView`（现状），多笔要一起看 |

不新增第二种就地样式。多笔就地铺开会把输入页变成一个列表页，而这页的职责只有一个：一句话进、一笔出。

## 7. 确认与防重

- **确认不能省，也不做自动保存。** 产品规则：AI 不得绕过用户确认写账本。`记上` 是唯一入口。
- 防重逻辑照旧：`记上` 之后走现有 `saveAll()` 那条路，撞上重复仍然弹现有的「可能已经记过」alert，两个按钮不变。少一次跳转不等于少一道确认——重复提示必须继续存在，它是账本正确性的一部分，不是流程装饰。
- 成功：草稿卡原地收成一行（`checkmark` 15 `ai` + 「记上了」15 `ink`），0.8 秒后整页 dismiss，回到首页；首页那一行新账淡入，不做额外的成功页、不做撤销（撤销本条是另一件事，这轮不加）。
- 失败：沿用现有失败卡（离线 / 超时 / Key 不对 / 模型不支持 / 本机规则没拆开），位置从页面底部移到输入卡正下方；按钮文案和动作不变。失败时输入框恢复可编辑，用户改一个字再发。

## 8. 深浅色

不新增任何色值：

| 元素 | 浅色 | 深色 |
| --- | --- | --- |
| 主按钮 | `accent` + `onAccent`（现状） | 同左 |
| 草稿金额 | `ink` | `ink` |
| 字段标签 | `ink2`（4.73:1） | `ink2`（7.18:1） |
| 类型胶囊 | `card2` + `ink2` | `card2` + `ink2` |
| 「改一下」 | `ink2` | `ink2` |
| 卡边 | `line` 0.5pt（必须有，canvas 与 card 只差 1.07） | 同 |

`ai` 在深色下是浅紫，**不要**在上面压白字；`onAccent` 在深色里本身就是深色，直接用。

## 9. 无障碍

- 主按钮：两种状态都是「记一笔」，但 hint 要跟着变——AI 开着时「打开一句话记账」，关着时「打开新账单」。外观一样不代表读屏也该一样。
- 输入框 label「一句话记账输入框」，hint「写一句话，按键盘上的发送」。
- 草稿卡：`.accessibilityElement(children: .combine)`，value 拼成「28 元，餐饮，今天，现金」；「记上」的 label 是「记上这笔账」，不要只说「记上」。
- 解析中：状态条 `.accessibilityLabel("正在整理")`，并让焦点从输入框移到草稿区（`@AccessibilityFocusState`）。
- 「改一下」44 点击区，但不能只靠颜色区别于主按钮——它在主按钮正下方、字号更小，位置本身就是区分。
- 动态字体：金额 34 用 `.system(size:)` 固定（钱数要一眼看准，不随字号变），其余全部语义字号（`.subheadline` / `.footnote`）。

## 12. 这轮不做

- 自动保存、停手自动解析（花钱 + 误发）。
- 就地改字段（改要走「改一下」进确认页）。
- 语音输入、Siri、快捷指令入口（另一件事）。
- 记完撤销、成功后编辑（另一件事）。
- 不改账本、统计、账单页的任何结构。
