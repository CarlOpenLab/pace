# Pace 边界案例清单（v1）

跨端一致性验收基线。所有案例已在 `shared/src/commonTest` 固化为测试；Android 与 iOS 必须通过共享核心得到相同结果。金额单位为分。

## 1. 金额

| # | 案例 | 期望 |
| --- | --- | --- |
| M1 | 0.1 + 0.2 元的两笔支出 | 求和为 30 分，不得出现 0.30000000000000004 |
| M2 | 输入 10.005 元 | 拒绝（超过两位小数），INVALID_AMOUNT |
| M3 | 金额 0 或负数 | INVALID_AMOUNT |
| M4 | 99999999999.99 元（10^13-1 分） | 允许 |
| M5 | 10^13 分 | INVALID_AMOUNT |
| M6 | 展示格式化 -3800 分 | 「超支 ¥38.00」，不输出 `-¥38.00` |

## 2. 日期/时区

| # | 案例 | 期望 |
| --- | --- | --- |
| D1 | 23:59 上海时间记账 | localDate 为当天 |
| D2 | 同一时刻在 UTC 时区（07:59）| localDate 同一天（上海）；若按纽约时区则为前一天 |
| D3 | 00:01 补记昨天的账 | localDate 取用户选择的归属日，不取系统当前日 |
| D4 | 跨年 12-31 23:59 → 01-01 00:01 | 两笔账单分属两个 localDate，本月统计各自正确 |
| D5 | localDate = 1969-12-31 或 2101-01-01 | INVALID_DATE |
| D6 | 用户携带设备旅行换时区 | 历史账单 localDate 不变（timezoneId 快照） |

## 4. 退款与转账

| # | 案例 | 期望 |
| --- | --- | --- |
| R1 | 退款无 refundOfId | REFUND_MISSING_ORIGINAL |
| R2 | refundOfId 指向 INCOME 账单 | REFUND_ORIGINAL_NOT_FOUND |
| R3 | 部分退款（原 5000 退 2000） | 原账单不变；退款日净支出 −2000 |
| R4 | 转账 100000 | 不计入支出统计与预算 |
| R5 | 信用卡还款记为 TRANSFER | 同 R4 |

## 5. 导入导出

见 `EXPORT_FORMAT.md` 第 5 节 E1–E6。补充：

| # | 案例 | 期望 |
| --- | --- | --- |
| I1 | MERGE 导入与现有账单 id 相同的记录 | 跳过，现有编辑不丢失 |
| I2 | REPLACE 导入过程中某条非法 | 整体回滚，原账本逐字节不变 |
| I3 | 导入 0 条账单的合法文件 | 允许，预览 count=0 |
| I4 | 备注包含逗号、引号、换行 | CSV 按 RFC 4180 转义，往返一致 |

## 6. 交互兜底

| # | 案例 | 期望 |
| --- | --- | --- |
| U1 | 断网状态完整记账、改账、看预算 | 全部可用 |
| U2 | 快速双击确认按钮 | 只产生一笔账单（指纹查重兜底 DUPLICATE_FINGERPRINT） |
| U3 | 删除账单后撤销 | 账单恢复且 localDate 等字段不变 |
| U4 | AI 关闭/失败 | 手动记账流程不受影响 |
| U5 | 清空数据误触 | 二次确认；取消不产生任何变更 |
