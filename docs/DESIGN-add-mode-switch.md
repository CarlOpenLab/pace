# 记一笔：一句话 / 手动 两个填法

替换掉之前按 AI 设置分叉的那套：主按钮永远进同一个「记一笔」页，页顶一个切换，默认停在「一句话」。一句话这条路不依赖 AI——没填 Key、AI 关着，本机规则照样拆。

本文只管版面和交互；文案以 Camo 的为准。

---

## 1. 切换器

**位置**：钉在导航栏下面，不随内容滚动。左右内距 20，上 8、下 12，底是 `canvas`，滚动的卡片从它下面穿过去。

**尺寸与颜色**（都写死，别让系统 segmented 接管）：

| 件 | 值 |
| --- | --- |
| 容器 | 高 34，圆角 17（胶囊），填充 `card2`，无描边 |
| 内距 | 3（上下左右一样），选中段就贴在里圈 |
| 两段 | 等宽各占一半，高 28，圆角 14 |
| 选中 | `accent` 填充 + `onAccent` 字 |
| 未选中 | 透明 + `ink2` 字 |
| 字 | 14 medium，单行，`minimumScaleFactor(0.85)` |

用 accent 填而不是白胶囊加阴影：这一页的选中语言就是「实底」，分类胶囊也这么画，同一个屏幕里不要出现两套选中表达。

**叫法**：`一句话` / `手动`。不叫「AI」——AI 关着的人也在用一句话这条路，键上写 AI 等于告诉他这条路没了。

**语义**：两个 Button（不是 Picker），各自 `accessibilityAddTraits(.isSelected)`，label 就是「一句话」「手动」，容器 hint「切换填法，已经填的内容不会丢」。

## 2. 两种填法各看到什么

**一句话**（默认）——这一屏只留三样，一句解释都不要：

1. 顶部切换器（§1）。
2. 输入卡：卡里**只有输入框**。没有小标题、没有 sparkles、没有说明行。
   - 卡：`card` 填充、圆角 20、横向内距 18、纵向内距 10（卡高 64），`paceCardFill(20)`。
   - 输入框：17 `ink`，单行，高 44，`.tint(PaceColor.ai)` 只留给光标，`.submitLabel` 按 Camo 的规则分「发送 / 完成」。
3. 例句胶囊一行：13 medium，`PillChipStyle`，间距 8，横向滚动，最多 4 个；**只在输入框为空、且还没有草稿时出现**。

解析中：一行 44 高，`ProgressView` 16 + 13 `ink2` 一行字，**放在草稿卡将要出现的位置**，别放在输入卡下面再让卡片把页面顶一下——原地换，不跳。

删掉的三处（上一版有、这版没有）：卡片顶上的小标题「说一句话，出几笔草稿」、那行「不联网、不出手机」的说明、最下面的「改成手动记账」按钮。说明那句挪到设置里填 Key 的地方（见 §9）。

这一屏的紫色只剩光标：卡片标题一删，AI 紫在页面上没有落脚点，别为了「显得智能」再加回来。

**手动**：
1. 金额卡（改造，见 §3）。
2. 归属卡：分类 + 日期 + 账户，一张。
3. 备注卡。
4. 计入预算（仅支出/退款），退款关联卡（仅退款）。

**不要**在一句话模式下把下面的表单露出半截让人往下滑——两屏就是两屏，切换器是唯一的门。

## 3. 手动这边的版式收拾（Carl 要的「布局优化」）

现在是 6 张卡，每张自带内距，滚到底要五屏。并成 4 张：

**卡 1 · 金额**：现在是大数字加一张独立的类型卡。把类型并进来——金额下面 12，一行四个胶囊（支出 / 收入 / 转账 / 退款），样式就是 `PillChipStyle`，选中 accent。四个在窄屏或大字号下横向滚动，不换行。理由：这笔多少、是进是出，是同一个判断的两半，分成两张卡等于让眼睛跳一次。

**卡 2 · 归属**：分类胶囊（现状）+ 一条 0.5 `line` 分隔（左缩进 `cardPadding`）+ 日期行 + 账户行（这两行现在是 dateAccountCard 里的，原样搬）。分类是最高频的一项，放最上面。

**卡 3 · 备注**：现状不动。

**卡 4 · 计入预算**：现状不动，仍然是「仅支出/退款」时出现。

顺序就是：金额 → 归属 → 备注 → 预算。第一屏要能看见金额、类型和分类，看不到日期算正常。

分隔线只有卡 2 里那一条：卡 1 的类型和金额之间不要线，那样会把一张卡切成两块。

## 4. 切换不丢东西

两边写的是同一笔账的不同填法，共用一份 @State：金额、类型、分类、日期、账户、备注、计入预算、退款关联。切换只换显示，不动值。

- 一句话 → 手动：如果刚解析出一张草稿，先把草稿的金额/类型/分类/日期/备注灌进表单再切（这就是 Camo 说的「把那句话带进表单」）；没有草稿就照旧显示原来填的。
- 手动 → 一句话：表单里的值一个不丢，切回去还在；已经打的那句话也还在输入框里。
- **切换本身永远不覆盖任何值。** 唯一会覆盖的是一次新的解析——那是用户按了发送的显式动作，而且结果会先以草稿卡出现，保存前还有一道「记上」。

## 5. 保存按钮

**一句话**：工具栏只留关闭。保存的唯一入口是草稿卡上的「记上」——值在卡上，动作就该在卡上。没有草稿时工具栏不放一个点不动的保存。

**手动**：工具栏关闭 + 保存胶囊（`ToolbarSaveStyle`，高 34、左右 14、可用 accent + onAccent、不可用 card2 + ink3）。

两处的胶囊是同一个样式、同一个位置（右上），只是「一句话」时它不出场——不是长得不一样，是不该出场。别在一句话模式下也给一个工具栏保存，那会变成同屏两个保存入口，正是我们前几轮一直在删的东西。

## 6. 一句话模式的出口

原来的「改成手动记账」那一条撤掉，切换器就是它。草稿菜单里那行按 Camo 的字，落成「退款或转账，切到手动」——词跟着切换器走，别再出现「手动记账」这个第三个说法。

## 7. 首页跟着改（Camo 那三条）

- 空状态合成一句：「点下面的「记一笔」，说一句话就行。」两个键删到一个。
- 主按钮读屏：「记一笔，打开记账页」，默认停哪边不读。
- 不再按 `ai.usesRemoteModel` 分叉主按钮的去向——去的是同一页。

## 8. 验收

1. 点主按钮 → 记一笔页，停在「一句话」，键盘已起。
2. 说一句、解析出草稿、点「记上」→ 落库；全程没出现工具栏保存。
3. 切到「手动」→ 刚那张草稿的金额/类型/分类/日期/备注都在表单里，类型那行是选中的。
4. 手动里改金额写备注，切回「一句话」再切回来 → 一个字没丢。
5. 手动模式点工具栏保存 → 和原来一样落库。
6. 编辑一笔已有账单时没有切换器，标题是「编辑账单」。
7. 大字号下切换器不换行、不截字（两段各缩到 0.85 也要塞得下）；类型四个胶囊横向滚动。
8. 一句话这一屏数一遍字：除了输入框里的示例和例句，没有第二句在解释这件事（没有小标题、没有联网说明、没有手动按钮）。
9. 解析中那一行原地换成草稿卡，页面不跳。
10. 设置里保存预算：不填时是灰的、点不动；填了按下变 accent 实底；成功后按钮文字变「已保存」，1.6 秒后回来，宽度不跳。

## 9. 设置页：保存预算要做成按钮

现在是 Form 里一整行文字，右边挂一个「已保存」——看起来像一条说明，不像能按的东西。

换成真按钮：

| 件 | 值 |
| --- | --- |
| 形状 | 占满整行宽的胶囊，高 50，圆角 `PaceRadius.block` |
| 可用 | `accent` 底 + `onAccent` 字，16 semibold，居中 |
| 不可用 | `card2` 底 + `ink3` 字，点不动 |
| 按下 | 透明度 0.85、缩到 0.97（和 `PrimaryButtonStyle` 同一套） |

- 和记一笔工具栏那颗保存是同一套长相（实底/灰底看能不能按），只是尺寸按表单来。
- Form 里要 `.listRowInsets(EdgeInsets(top: 8, leading: 0, bottom: 8, trailing: 0))` 加 `.listRowBackground(Color.clear)`，让胶囊真的撑满，不出现在白色行里
- 一行胶囊中间。
- 「已保存」不再挂在行右边：保存成功后按钮上的字换成「已保存」，1.6 秒后换回来。按钮宽度固定，字变了不会跳。
- 校验失败时按钮是灰的、点不动；红字错误行留在按钮下面，位置不变。

**挪过来的那句隐私说明**：填 Key 的地方，Key 输入框下面一行 12 `ink2`。它不是装饰，是这个功能的边界，别藏进 tooltip。

## 10. 一句话的失败卡（最长那句也放得下）

一条失败卡：标题 + 正文 + 两颗按钮。文案以 Camo 的为准，最长的一句是「你填的服务没能把这句话拆成账单。换句话再说，或者手动记。账本没有任何变化。」

| 件 | 值 |
| --- | --- |
| 卡片内距 | 20 |
| 标题 | 15 semibold `ink` |
| 正文 | 13 `ink2`，行距 3，**不限行数、不截、不缩** |
| 标题→正文 | 8 |
| 正文→按钮 | 16 |
| 卡高 | 跟着内容长，不设固定高度 |

两颗按钮：「用本机规则再试」「切到手动」，都是次级玻璃，命中高 44，离卡片边至少 12 点。

- 放得下就并排，间距 8；放不下就上下两行、各自占满卡片宽度，间距 8。用 `ViewThatFits`。
- 不为了塞进一行缩字——字号是用户选的，这条和首页日期那条同一个道理。
- 「切到手动」按下去，刚才那句话留在输入框里，切回来还能再试；它只切填法，不带任何别的状态。

### 10.1 正文很长的那种失败卡：按钮放到原因列表之前

有的失败卡正文不是三句，而是一个原因列表（导入/恢复失败：金额不对、日期不对、类型不认识……最多五行）。这种卡在最大档下会长到一屏放不下，「标题、正文、按钮同时在框里」就不成立了。

所以**按钮放原因列表之前**，读法是：标题（没成什么）→ 正文（账本现在什么状态）→ 按钮（下一步做什么）→ 原因列表（哪儿不对）。

- 理由：这一屏唯一必须立刻可做的动作是那颗按钮；原因行是用来看的，不是用来按的，放在按钮后面，滚不滚都不耽误人往下走。
- 验收也跟着分：带列表的卡要「标题、状态句、按钮三样同时在框里」，原因行允许在下面滚；不带列表的短卡（「连不上网」那张）仍然要求「标题、正文第一句、两颗按钮同时在框里」。
- 两张卡不该为了统一长成一个样：一个正文三句、一个正文五行，结构上的差别是内容带来的，不是不一致。
